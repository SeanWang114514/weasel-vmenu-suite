# 小狼毫 v 功能 · 使用说明

## 语音输入（长按快捷键说话，默认 Ctrl+Win）

**按住 Ctrl+Win 不放**（长按约 0.15 秒；这个组合**可以在设置窗口里改成任意
Ctrl/Alt/Win 组合**，见下面「改快捷键」一节），屏幕最下方中央浮出一个 **Apple 风格白色
胶囊**（约 100×46，是初版的 1/3 长、1/2 高）：systemBlue 圆形麦克风徽章 + 右侧
6 根 Blue→Teal 渐变声波条 + 徽章外呼吸光环。**无文字状态行**，状态全靠徽章图形表达：

1. 浮出即开始录音：徽章是**蓝色麦克风**，呼吸光环扩散，声波条随声音居中跳动；
2. **松开 Ctrl 或 Win 任意一个**即结束录音（点一下胶囊也行），进入识别；
3. 识别完成：徽章变**绿色 ✓**（文字已打进当前光标处）；没识别到文字/打不开麦克风则
   变**橙色 ！**，胶囊自动收起。上屏用 `SendInput` Unicode 注入，**不动剪贴板、
   不经过输入法**。

细节规则：

- **短于 0.15 秒的点按不响应**（防误触）；录音不足 0.25 秒视为没说完，静默丢弃；
- 按住期间出现**第三个键**（Ctrl+Win+D 这类系统组合）→ 立即中止，不上屏；
- 上屏前会**等 Ctrl/Win 全部松开**（最长 120 秒），绝不把修饰键状态带进目标窗口
  变成快捷键；
- 录音最长 60 秒自动结束；没识别到文字徽章显示橙色 ！，不输出空内容。

**怎么保证不把输入法搞崩**：悬浮球是**完全独立的 pythonw 进程**（`voice-overlay.py`），
输入法本体（WeaselServer / Lua / YAML）**一行都没改**。热键检测用的是
`GetAsyncKeyState` **轮询**（20ms）——**完全不装系统键盘钩子**，只读不写，
本进程哪怕立刻卡死，系统键盘、输入法切换、Win 键也**完全不受影响**。

> 🐛 踩坑记录（已修复）：初版用 WH_KEYBOARD_LL 钩子观察按键，但 ctypes 不声明
> argtypes 时会把 64 位 `lParam` 截断成 32 位传回 `CallNextHookEx`，损坏下游
> 钩子链 → **全系统无法打字、无法切输入法、Win 键无反应**。教训：ctypes 调用
> Win32 **必须显式声明 argtypes/restype**；涉及系统输入链的逻辑宁可用轮询。

> 🐛 第二个坑：轮询扫描「第三个键」时必须跳过 `0x10/0x11/0x12`
> （Shift/Ctrl/Alt 的**通用 VK 码**）—— 按住任意一侧 Ctrl 时
> `GetAsyncKeyState(0x11)` 也返回按下，不排除会把你自己按的 Ctrl 误判成
> 第三键、每次长按都立刻中止（`SCAN_SKIP` 常量）。

**识别后端（重要改动）**：此前用 vosk 小模型，准确率一般；现在改为
**Qwen3-ASR-0.6B**（官方 `ggml-org/Qwen3-ASR-0.6B-GGUF`，带标点）：

- 悬浮球启动时后台自动 `llama-server`（`127.0.0.1:3966`，约 1.5s 就绪，常驻
  ~1.1GB 内存），已存活则复用，**不需要手动启动**；
- 每次松开后把录音 WAV POST 到 `/v1/audio/transcriptions`（热请求 ~0.2s）；
- **任何失败（server 没起来/超时/报错）自动降级 vosk**，识别永远可用；
- 手动测试：`curl -X POST http://127.0.0.1:3966/v1/audio/transcriptions -F "file=@test.wav" -F "model=qwen3-asr" -F "language=zh"`
- 想再准一点可换 **1.7B**（`handy-computer/Qwen3-ASR-1.7B-gguf`，Q4_K_M 1.26GB，
  内存占用更高），改 `voice-overlay.py` 里的 `ASR_MODEL`/`ASR_MMPROJ` 即可。

**流式输出（边说边打进输入框）**：按住期间**不必等松开**，识别结果会
一边说一边落到光标处：

- 录音累计 **0.6 秒**后开始流式，之后每 `min(1s, max(0.4s, 时长×0.08))`
  识别一次当前已录到的全部音频，把**新增的字**用 `SendInput` 直接注入
  （按住期间注入已实测可正常落字）——相比旧参数（1s 起步、0.6s 间隔、
  15% 降频），首字约提前 0.5 秒，长句后半段刷新频率翻倍；
- 只发送「**连续两轮识别一致**的稳定前缀」的增量——首轮只播种不下发，避免打出
  会被推翻的内容；模型回头改写已上屏的字时，若**错位不超过 max(4, 已上屏/3) 字**
  就**前向续发**尾巴（按住期间修饰键被占、退格有护栏根本不能用，冻结只会让整句
  停摆到松开——实测日志 revise deferred 连刷 5 秒）；错位超过阈值的大改写
  才继续冻结，等最终对账；
- **松开后做最终识别对账**：前缀一致 → 只补尾巴（零退格，最常见）；模型改写了
  已上屏的部分 → 退格删掉已注入的再发最终版（含前向续发留下的错位中段）；
  最终为空但流式已有字 → 保留已上屏
  的（宁可留字不瞎删）。退格有**两道硬护栏**：**Ctrl/Win 还按着就绝不退格**
  （按着 Ctrl 按退格在多数编辑器是「删一个词」，会删过头）、**前台窗口不再是
  本轮目标窗口也绝不退格**（识别那零点几秒里用户切走了窗口的话，按 VK_BACK
  会删掉新窗口里他自己的内容，且不可撤销）——任一不满足都宁可放弃校正、
  把文字原样留着并记日志；
- 对账与单轮流式的判定都是**纯函数**（`reconcile_plan` / `stream_round`），
  实机与 `--selftest`、`voice-punct-test.py --stream` 跑的是同一份逻辑，
  避免「测试里复刻一份、改一处忘一处」；selftest 还用**虚拟屏幕**断言
  不变量：流式续发 + 对账跑完后屏幕内容必须恰好等于最终结果，退格数必须
  恰好等于已注入字数（多退一格会吃掉用户原有文字，少退会留下错位垃圾）；
- 按住期间出现第三键中止时，已流式上屏的字会**异步撤回**（等修饰键松开、焦点
  没变才退格；焦点变了就原样留着并记日志）；
- 录音期间焦点窗口切换 → 立即停止流式，绝不把字打进别的窗口；
- server 挂掉 → 停止流式，走原有 vosk 最终识别兜底；
- 无清晰语音时模型可能回声 server 的英文提示词（`Transcribe audio to text …`），
  已做过滤，绝不把这段英文打进输入框。

**标点符号 → 空格**：识别结果里的标点默认**全部换成空格**（连续空格合并、首尾去掉），
所以「今天天气真好，我们去散步吧。」会打上「今天天气真好 我们去散步吧」。
数字里的小数点 / 千分位（`3.14`、`1,000`）会被保留，不会被拆开。
开关在**设置窗口 → 「语音输入」页**，改动即时保存、**下一次识别即生效**（不用重启悬浮球）；
状态存在 `D:\rime-sandbox\voice-settings.txt` 的 `punct_to_space`。
流式增量与最终结果走的是同一个变换，所以边说边打的过程中也不会出现标点与空格来回跳。

**自启动**：已挂进 `clipboard-sync.bat`（和剪贴板同步、设置窗口一起启动）。
**开机自启已配置**：`shell:startup` 里放了 `语音输入悬浮球.lnk`（指向上面那个 bat），
所以重启电脑后悬浮球会自动跑起来——之前「重启后按 Ctrl+Win 没反应」就是因为
进程没起来。

### 改快捷键（设置窗口 → 「语音输入」页）

快捷键**可以自己改**：打开设置窗口（双击 `打开设置.bat`，或输入法里 `v` → `1`），
切到「**语音输入**」页，下面那张「**语音输入快捷键（按住说话）**」卡片：

1. 点蓝色按钮「**点击录制**」；
2. **直接在键盘上按下你想要的组合**（例如先按住 `Ctrl`，再按 `Alt` + `空格`），
   **全部松开即录入** —— 不用打字母、不用填表；
3. 按钮立刻显示新组合（如 `Ctrl + Alt + 空格`）并写进配置，**下一次按键就生效，
   不用重启悬浮球**。按 `Esc` 或再点一次按钮 = 取消录制；「恢复默认」一键回到
   `Ctrl + Win`。

规则与保护（写入前逐条校验，不合法当场提示、不保存）：

- 必须包含 **Ctrl / Alt / Win** 之一 —— 只有 Shift 的话 `Shift+字母` 就是普通打字，
  一按就开录，会被拒绝；
- **不能单独按 Win**（会弹开始菜单）、最多 4 个键、不能重复；
- **只提醒不拦截**：按住期间**目标软件也会收到这些按键**（含长按自动重复），
  所以别选 `Ctrl+C` / `Ctrl+V` 这类会真执行的组合（按钮旁会变橙色提示）；
  `Ctrl+空格` 和小狼毫的中英切换冲突，同样会提示；
- **录制期间悬浮球自动暂停检测**：配置里会临时写一行
  `hotkey_recorder_pid=<设置窗口进程 pid>`，悬浮球查到这个进程还活着就先不检测，
  录完自动清掉（窗口被关掉、进程意外退出也一样会清）——
  所以「录制」这个动作本身绝不会被误当成一次长按触发。

配置存在 `D:\rime-sandbox\voice-settings.txt` 的 `hotkey=` 字段（和 `punct_to_space`
同一个文件）。悬浮球每 0.4 秒看一次文件改动，**改完即生效**；文件被手改成非法值会
自动退回 `ctrl+win`，日志里会写明原因。

```powershell

python D:\VibeCoding\输入法\voice-overlay.py --simulate    # 完整模拟一轮（不上屏）
python D:\VibeCoding\输入法\voice-overlay.py --simulate --canvas  # 同上但强制 Tk 画布（新旧渲染对比）
```

**UI 清晰度（逐像素 alpha 抗锯齿渲染）**：悬浮球进程在创建窗口**之前**先
把自身设为 DPI 感知（Per-Monitor V2，失败降级 shcore / `SetProcessDPIAware`），
然后走**分层窗口**渲染：

- **为什么不能继续用 Tk 画布**：Tk 画布**没有任何抗锯齿**，圆角、圆形徽章、
  声波条全是硬边像素；`-transparentcolor` 又只有 1-bit 色键透明，边缘抗锯齿
  像素会和色键混出彩色镶边。所以不管 DPI 提多高，都只能得到「锐利但毛糙」
  的边缘（放大看就是阶梯）。
- **现在怎么做**：Pillow 按 **4× 超采样**（4×4=16 个样本/像素）绘制，再用
  Lanczos 缩到物理像素 —— 边缘真正平滑；窗口用 Win32 **WS_EX_LAYERED +
  `UpdateLayeredWindow`** 推 32 位预乘 BGRA 位图，**逐像素 alpha** 与桌面真实
  混合，因此还画得出**悬浮投影**和胶囊的**玻璃质感竖向渐变**（纯白 → 极淡的
  `#F2F3F7`），而不是靠色键硬抠。
- 设计稿仍是 100×46 逻辑像素，窗口额外留 12 逻辑像素给投影，所以物理窗口是
  **186×105**（胶囊本体仍是 150×69）。渲染耗时约 5ms/帧（动画节拍 60ms），
  静态部分（投影/胶囊/徽章/图形）按「图形 × 徽章色」缓存，每帧只重画声波条
  与呼吸环。
- 分层窗口自带 `WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE`：不占任务栏、不抢焦点；
  透明区域天然**点击穿透**，只有胶囊本体可点（点胶囊=开始/结束录音，靠窗口
  消息回调转入事件队列，已实测）。
- **不抢焦点（实测）**：胶囊显示前后前台窗口保持不变 —— 这才保证文字上屏到
  你原来那个输入框，而不是被胶囊自己接走。另外修了个既有小毛病：Tk 建根窗口
  时会 map 一次，即使紧接着 `withdraw()`，Windows 也可能把前台留在那个已隐藏
  的 Tk 窗口上（表现为「刚启动那会儿打字没反应」，开机自启最容易撞上）。现在
  启动前先记下前台窗口，建完窗口再 `SetForegroundWindow` 还回去，日志写
  `restore focus -> hwnd=... ok`。
- **回退**：Pillow 缺失或分层窗口创建失败时自动退回 Tk 画布（无抗锯齿但一定
  能显示，绝不罢工），日志会写 `view=canvas ...`；`--canvas` 参数可强制用
  Tk 画布，用来做新旧渲染对比。日志开头会打印
  `view=layered win=186x105 ss=4x supersample` 与 `dpi mode=pmv2 scale=1.50`。

> ⚠️ 屏幕截图验证时注意 DPI：这台机器 2560×1440 / 150%，PowerShell 截屏前要先
> `SetProcessDPIAware()`，否则只截到左上角 1707×960、看不到底部中央的胶囊
> （排查时曾误判「胶囊没显示」就是这个原因）。
> 另外色号要用**像素采样**核对，别信肉眼/模型描述：分层窗口的 DIB 字节序必须是
> BGRA，`PIL.split()` 返回的是 R,G,B,A —— 少换一次序整块色相会 R/B 互换
> （蓝徽章渲染成橙色，曾真的踩过）。

## 前后鼻音模糊拼音（逐对开关）+ 中文模式英文候选

设置窗口 →「设置与缓存」页，两张卡片，**改动即时保存**：每次最多约 1 秒后在输入法里
生效，**不用重新部署、不用重启输入法**。

**① 前后鼻音模糊输入（`fuzzy_filter.lua`）**

- **总开关**：一键开 / 关全部前后鼻音模糊；关掉后行为与原生雾凇完全一致。
- **五对逐对开关**，可以只模糊其中几对：
  - `an` ↔ `ang`（实测：关掉后打 `yinda` 不再出「硬 ying 打 / 应 ying 答」，开则出现，
    注释里带真实拼音）
  - `en` ↔ `eng`
  - `in` ↔ `ing`（实测：单独关这一对，`yinda` 的「硬 / 应」消失，其余不受影响）
  - `ian` ↔ `iang`
  - `uan` ↔ `uang`
- 判定基于候选注释里的真实拼音，只影响这五对；认不出的派生写法（`ong` 之类）不受逐对
  开关管，只跟总开关。
- 写入 `D:\rime-sandbox\fuzzy-settings.txt`：`nasal=`（总开关）+ `nasal_an_ang=` …
  `nasal_uan_uang=` 五对；字段缺失按「开」处理（与旧版 `nasal=true` 行为一致）。

**② 中文模式下的英文候选（`en_gate.lua`，「按键设置」卡片里）**

- 默认**开**：输入 `apple` 第一页就是 apple / apples / applet / Apple ID……（原生行为）。
- 关掉：纯英文候选整页消失，只剩中文候选；中英混排词（含中文字符）、日期、UUID 不会被
  误伤，v 菜单里的剪贴板英文照常显示。
- 写入 `D:\rime-sandbox\candidate-settings.txt`：`en_candidates=true|false`
  （字段缺失 / 文件不存在按「开」处理）。

两张卡背后都是 `D:\rime-sandbox\lua\` 里的 lua 滤镜，每秒最多读一次开关文件，
**不启动任何进程、不改方案文件**；只有改了 lua 源码本身才需要重启 `WeaselServer.exe`
（`%APPDATA%\Rime\lua\` 下有同步副本，两处 MD5 一致）。

## 常用语怎么用

> 「常用语」就是原来的「收藏」，只是改了个更好懂的名字 —— 数据、编码、文件位置全都没变，
> 你之前加的条目一条都不会丢。

现在有两条路，日常用第一条：

1. **正常打字时**（不用按 `v`）：键入常用语**编码的前 3 位**，内容就会出现在
   **候选第 2 位**，按 `2` 上屏。

   - 例：编码 `wsl` → 打 `wsl` → 第 2 个候选就是 `wslzhenshuai@163.com`，注释显示「常用语」。
   - 例：编码 `wsl123` → 打 `wsl` 就会提前出现（前 3 位就算命中）。
   - **纯数字编码**（例如 `131`）：数字**不再被当成候选吃掉** —— 你照常往后接符号、接数字都行。
     规则是：

     | 你输入 | 结果 |
     | --- | --- |
     | `13` 再按 `-`（或 `=`、`+`、`.`） | **先上屏 `13`，再接上那个符号** → `13-`、`13。`、`13=` |
     | `131` 再按**回车** | 上屏**整条常用语**（`13122500717`）—— 回车是**唯一**会打出完整常用语的键 |
     | `1313`（接下去组不成任何编码） | 就是 `1313`（数字老老实实跟在后面） |
     | `1312`（数字键不再选到那条常用语） | 就是 `1312` |
     | 只打了 `1` | 数字留在输入框里（`1` 是 `131` 的起点），候选栏会**自动预览**那条常用语，继续打数字就是接着往下加 |

     （全数字输入时候选栏只有一条「常用语预览」，**没有序号**—— 看到常用语就知道对了，
     按回车上屏；打别的数字或符号就自动追加。）

   **编码打完直接按回车**：输入和某条编码**完全一样**时按回车，常用语内容直接上屏，
   不用再去按候选数字。字母编码和纯数字编码都支持：

   | 你输入 | 按回车的结果 |
   | --- | --- |
   | `wsl`（正好是一条完整编码） | 上屏该条常用语内容 |
   | `ws`（只是编码前缀） | 上屏 `ws`（没打完就不抢） |
   | `131`（正好是一条完整编码） | 上屏该条常用语内容 |
   | `12345`（不是任何编码） | 上屏 `12345` |

2. **`v` → `3`**：搜索式取用，可以再输入编码片段过滤。

## 候选框：默认收起，按 `↓` 展开成 4 行 × 9 列

**默认是收起的 9 个候选**，**排成一行**，**框的宽度跟着候选词的实际内容走**
（候选词短 → 框窄，候选词长 → 框宽；不会把所有格子拉成一样宽）。
如果这行候选词太长（框超出了上限 1100 像素），会**自动少显示末尾的几条**（至少留 3 条）。

**按一下 `↓`** 就会展开成一个 **4 行 × 9 列**的方格（最多 36 个）：
展开后每列的宽度**统一成最长候选词的宽度**（保证行列对齐）。

| 按键 | 行为 |
| --- | --- |
| `↓`（还没展开时） | **展开**成 4 行 × 9 列（当前选中的那个不变） |
| `↓`（已展开） | 高亮**跳到下一行**（不收起） |
| `↑`（高亮在第 1 行） | **收回**成收起状态 |
| `↑`（高亮在第 2–4 行） | 高亮**跳到上一行** |
| `←` / `→` | 高亮**在同一行内左右移动** |
| `+`（小键盘） | **下翻**：换下一批 9 个 |

> **收起再重开 = 永远第 1 屏**（0.2.22 起）：翻到第 2 页后按 `↑` 收起、再按 `↓` 重新展开，
> 展示的**一定是最前面的那批候选**，不会停留在收起前的旧页；收起后的那一行同样回到第 1 屏。

> **选词也可以用数字键**（`1`–`9` 选高亮那一行的第 1–9 个，`0` 是第 10 个）。

**序号**：展开后**只有高亮那一行带 1–9**，其余行左边是干干净净的候选文字（不会再有
`10`、`11`……）。序号只用来显示，**不会混进上屏文字** —— 打 `shi` 按空格还是上屏「是」，
按 `3` 还是上屏「师」。

**这一项目前已经开好了**，不用做任何事。它由三个配置决定（都不是输入法里的开关，
改完要重启输入法服务 `WeaselServer` 才生效）：

| 想改什么 | 改哪个键 | 现在 | 怎么改 |
| --- | --- | --- | --- |
| 候选框**最宽多少**（长英文候选不会再把框拉满屏） | Weasel 主题 `style/layout/max_width` | `1100` | 调小 → 框更窄（超长候选自动用 `…` 截断显示，**上屏内容仍是完整的**）；调到 `1800` 以上 → 长英文候选又会接近满屏 |
| 一行放几个 / 换行 | **输入法自己算**（自编 `HorizontalLayout.cpp`） | 候选 ≤ 9 个排**一行**；> 9 个每 9 个换一行 | 不用改配置；`max_width` 只决定「一行最宽画到哪」 |
| 一页最多几条 | 方案 `menu/page_size` | `36` | 展开后的总数，= 列数 × 行数（9 × 4）；改回 `9` 就是原来一条候选栏的条数 |
| 要不要原生序号 | Weasel 主题 `style/label_format` | 空（`""` / `" "` 都行） | 改回 `"%s"` 就是原来那种「1. 2. 3. …」（第 10 个之后会显示 `10`、`11`） |

**长英文候选（`gith`、`vscode` 这类）**：以前 9 条候选每条都很长时，框会一路长到几乎顶满整屏
（实测 `1656` 宽 / 屏宽 `1707`）。现在会**先少显示末尾最多 3 条**，再不够就把每格压窄、
多出来的字画成 `…` —— 同一个 `gith` 现在只有 `1122` 宽（约屏幕的 2/3），一行能看到 6 条。
（被省掉的那几条**仍能用数字键选中**：按 `7`/`8`/`9` 会上屏看不见的第 7–9 条。）

**怎么关**（回到原来一条长候选栏）：把 `max_width` 改回 `0`、`page_size` 改回 `9`、
`label_format` 改回 `"%s"`，然后重启输入法服务。
文件位置：`D:\rime-sandbox\weasel.custom.yaml` + `D:\rime-sandbox\build\weasel.yaml`（`max_width` 与
`label_format`），`D:\rime-sandbox\rime_ice.custom.yaml` + `D:\rime-sandbox\build\rime_ice.schema.yaml`
（`page_size`）。

> 小提示：`%APPDATA%\Rime\build\weasel.yaml` 是**旧副本、不生效**（实测那里还停在 `max_width: 300`），
> 改 `D:\rime-sandbox` 里的文件就够了。

> ⚠️ 这两个 `.yaml` 必须用 **UTF-8** 方式改。别用记事本随便存成 ANSI，
> 也别用 PowerShell 的 `Set-Content` —— 会写坏文件，写坏之后**打字时一个候选框都不显示**。

## 下一个候选词预测（「上一个词」猜「下一个词」）

**刚上屏一个词，接着打它后面那个拼音，最可能接的字会自动排到第 1 位**：

| 刚上屏过 | 接着输入 | 候选变化 |
| --- | --- | --- |
| 「眼睛」 | `jing` | 「睛」从第 6 跳到第 1（第 2 位「镜」= 眼镜） |
| 「河北」 | `jing` | 「京」从第 8 跳到第 1 |
| 「太」 | `yang` | 「阳」排第 1（本来也是第 1，由语料概率背书） |

规则与边界：

- **算法 = 字级二元统计**（上一个字 → 下一个字），语料是 10.5 亿字符的中文维基百科全量（6 个分片）；
  候选首字的条件概率 **≥ 2%** 才会被提前（最多提前 3 个，按概率降序），其余候选保持原顺序；
- **长段文字里一样有效**：预测取「当前组合里已锁定的汉字」（逐段选词时也能跟上），
  整段上屏时取上一次上屏词的**最后一个字**；标点 / 回车 / 英文上屏会重置上下文，跨句不瞎猜；
- **不参与**：`v` 菜单、部件反查（`u` 开头）、英文模式（Shift 切走）；
- 没有上下文、或没有候选过线时**完全原样放行** —— 不会凭空把某个词顶上来；
- 数据文件 `predict-bigram.txt`（**12 MB**，11773 个上字；100 MB 预算只用了约 1/8）放在输入法用户目录，
  **服务启动时一次性读进内存（约 30 ms），打字路径零磁盘读取**；文件不存在时功能自动静默关闭。

换语料重建数据：`python corpus\build_bigram.py <语料.txt> predict-bigram.txt`，
把产物拷成 `D:\rime-sandbox\predict-bigram.txt`，再重启输入法服务即可。

## 快捷输入（`v` → `3`）：计算、日期、农历、数字大写、部件拆字…

按 `v` 再按 `3`（或者 `v` 之后直接按下面那个**字母快捷键**，例如 `v` `c`），会出现这样**一行**，
**按哪个数字（或字母），那个功能就直接启用**，接着输入就行：

| 数字 | 字母 | 菜单文字 | 按完之后怎么用 |
| --- | --- | --- | --- |
| 1 | `c` | 计算 | **接着把算式打完**（如 `1+2*3`），候选第一项就是结果 `7`，空格或回车上屏。例：`9*9` → 81 |
| 2 | `r` | 日期 | 直接出今天的日期（如 `2026-09-13`） |
| 3 | `s` | 时间 | 直接出当前时间（`02:30`） |
| 4 | `n` | 农历输入 | 直接出**今天**的农历（如 `丙午马年八月初三`）—— 它已经帮你把今天的日期填好了；想查别的日子，把后面那串数字改成那天的日期 |
| 5 | `h` | 数字货币转写 | 接着输入数字：打 `1234` → `一千二百三十四`（前缀 `R` 已经填好） |
| 6 | `u` | Unicode | 接着输入十六进制码：打 `4e2d` → `中`（前缀 `U` 已经填好） |
| 7 | `q` | 返回 | 回到 `v` 主菜单 |

**原理一句话**：选中一项后，它只是帮你把「触发字母」打进输入框（比如计算是 `cC`、日期是 `rq`），
之后**完全交回输入法原本的处理** —— 这些能力都是雾凇拼音自带的，所以效果和手打那些字母一模一样，
只是不用记它们。三个注意点：

1. **「计算」按了 1 之后必须接着打算式**（只打 `cC` 是不会出结果的，这是雾凇拼音的规则）。
2. 「数字货币转写 / Unicode」按完还要自己补内容（`1234` / `4e2d`）。
3. 「农历输入」按 4 的时候已经带上今天的日期，所以立刻就能看到今天的农历。

### 部件拆字也能直接打字（不用进菜单）

直接输入 **`u` + 部件拼音**就行：`unvzi` → **好**、`uriyue` → **明**。

> 注意：0.2.3 之后部件拆字的前缀是**单个 `u`**，以前那种 `uUnvzi` 的写法**已经不用了**（也失效了）。
> 副作用是：以 `u` 开头的英文词也会被当成拆字 —— 要打英文请切到英文模式（`Shift`）或直接回车。
> 想改回 `uU`：把 `D:\rime-sandbox\rime_ice.custom.yaml` 里的 `radical_lookup/prefix` 改回 `uU`、
> `recognizer/patterns/radical_lookup` 改回 `^uU[a-z]+$`，重启服务。

| 按键 | 作用 |
| --- | --- |
| `v` | 打开功能菜单（候选 **5 项，排成一行**：设置 / 剪贴板 / 快捷输入 / 常用语 / 原符号） |

| `v` → `3` | **快捷输入**：计算 / 日期 / 时间 / 农历输入 / 数字货币转写 / Unicode / 返回（见上一节；也可以直接按 `v` + 字母快捷键） |

（「文字设置」那套纯键盘菜单（`vset`）代码还在，只是不再挂在 `v` 菜单上 ——
第 5 项现在是「快捷输入」；现在只有手动打出 `vset` 才进得去，普通使用不需要它。）

## 防误触（敲太快的键会被忽略）

两次按键的间隔小于阈值时，**第二下直接被吞掉**（不进任何分支、绝不会上屏）—— 用来挡住
手抖 / 连击把 `v` 功能敲出半截。在设置窗口的「防误触」页里可以开关、拖滑块、点
「↺恢复推荐30ms」、保存；值写在 `vmenu-settings.txt` 的 `misinput_protect` /
`misinput_interval` 两个字段。输入法**每次按键都实时读取**，保存后立刻生效，不用重启。

小提示：被防误触吞掉的键、以及 v 功能里「这一屏没有可选候选」时的空格，都只是这一次
没反应 —— 内部编码（如 `vclip`）绝不会被打进文档（0.2.21 修复）。

## 网址 / 路径智能标点（。→.、→\）

打网址或 Windows 路径时不用再切英文：

- **网址**：`www.baidu.com`、`google.com` 等按完直接原样上屏，中间的 `。` 自动变 `.`；
  `https://`、`ftp:`、`mailto:`、`file://` 开头的一律原样直通。
- **路径**：`D:\软件` 里盘符后的 `：` 自动变 `:`，紧跟的 `、` 自动变 `\`，
  后面继续正常打拼音（`D:\软件` 直接出 `D:\软件`）。
- **不影响拼音**：`nihao.` 还是 `你好。`、`baidu` 还是 `百度` —— 只有**确实不像拼音**
  的输入才按网址处理（拼音校验器把关）。

开关：设置窗口勾选/取消「网址/路径智能标点」（默认开），写入
`smart-punct-settings.txt` 的 `smart_punct=true|false`，输入法每秒内实时读取，
保存后立刻生效，不用重启。关闭后全部恢复小狼毫原生标点行为。

## 后台常驻（`VMenu.exe`）+ 后台服务

现在的常驻链条是**两个原生小程序**，零 PowerShell：

| 进程 | 作用 |
| --- | --- |
| `VMenu.exe`（`D:\rime-sandbox\VMenu.exe`，11.5KB，无控制台） | 三种角色都在它里面：<br>· **`open`** —— 打开设置窗口（写标记文件；常驻实例在就让它自己亮出来，不在就把守护拉起来）。托盘菜单、`打开设置.bat`、开始菜单快捷方式走的都是它。<br>· **`watch`** —— 守护：常驻窗口没在跑就把它（无控制台地）拉起来。判断「在不在」用的是命名互斥体 `RimeVMenuSettingsGui`（约 0.1ms），不再去枚举进程。<br>· **`sync`** —— 剪贴板同步子进程：循环把系统剪贴板同步进 `clipboard-cache.txt`（去重、一行一条、最多 50 条、互斥体 `RimeClipboardSync`），逻辑直接编在 exe 里。<br>· **`start` / `stop` / `status`** —— 一次启动全部（守护 + 剪贴板同步 + 窗口）/ 全部停掉 / 打一份状态到 `%TEMP%\vmenu-status.txt`（最近一次实测四项全「在跑」）。开机自启的那条注册表项就是 `"...\VMenu.exe" start`。 |
| `VMenuSettings.exe` | 常驻的设置窗口（C# WinForms，86KB、约 17MB 内存，就是上面那个可视化窗口）。输入法按 `v` `1` 时只写一个标记文件 `open-settings.flag`（**绝不自己启动进程**），窗口每 60ms 看一次这个文件。源码：`D:\VibeCoding\输入法\VMenuSettingsSrc\`（`Ui.cs` / `Data.cs` / `MainForm.cs` / 各页 / `HotkeyKit.cs` / `Program.cs`）。 |

> **必须在输入法进程之外读剪贴板**：在 Rime 输入线程里读剪贴板正是之前 v2 卡死的根因
> —— 所以 `sync` 是独立子进程，设置窗口、输入法都不碰它。

窗口消息循环是标准 WinForms `Application::Run`：每 60ms 只做一次
`File.Exists(标记文件)` 快检查（命中才读写文件），剪贴板 / 保活检查每 1.5 秒一次。
实测设置窗口打开延迟 **55~123ms**，空闲 CPU 只有个位数百分比以下（C# 版比旧
PowerShell 版更省内存：常驻约 17MB vs 约 150MB）。

> 历史备注：旧的 PowerShell 版窗口曾因 `FileSystemWatcher` 回调跑在线程池（没有
> PowerShell 运行空间、未处理异常直接杀进程）而「写一次标记文件就崩一次」，所以一直用
> 轮询；换成 C# 后保留了这个又稳又快的 60ms 快路径。

**启动 / 重启整套：双击 `clipboard-sync.bat`**（它会先 `VMenu.exe stop` 再 `start`，
保证各只有一个，最后顺手把设置窗口打开）。

如果 `v` → `1` 没反应，说明后台服务没在跑：双击 `clipboard-sync.bat`，
或双击 `打开设置.bat`。之后 `v` → `1` 就一直是一按就出。

## 已知限制

- 常用语的「正常打字命中」只在**中文模式**生效，且需要编码至少 3 位（不足 3 位的编码
  只能用 `v` → `3`）。纯数字编码要把编码打完才会出现。
- 回车上屏常用语要求输入**与编码完全一致**：只打了前几位（前缀）时，回车仍然是原样上屏，
  不会抢走你的正常输入。
- **候选框的「收起 / 展开 / 序号」没有输入法里的开关**：宽度与序号由主题（`max_width`、
  `label_format`）、条数由方案（`page_size`）决定，改完必须重启服务才生效
  （见上面「候选框：默认收起，按 `↓` 展开」）。
- **方向键不能移动选中项**（只有 `↓` / `↑` 能展开、收起）：小狼毫的 Lua 接口里没有这个能力，
  选词请用数字键（前 9 个用 `1`–`9`，第 10 个用 `0`）或空格（第 1 个）。
  想让它支持，需要改小狼毫本体 —— 正在确认要不要做。
- **序号只在展开后的第一行**（1–9），第 2–4 行没有序号；收起时 9 个候选排成两行，
  第二行那两个也会带 `8`、`9`（序号是按候选顺序给的，属正常现象，不影响打出来的字）。
- **`v` 菜单里的「返回」前面会显示 `10`**（它的按键其实是 `q`），只是观感问题。
- **快捷输入不是每一项都能「选完就出结果」**：「计算」要在 `cC` 后继续打算式；
  「数字大写 / Unicode / 部件拆字」要自己补内容（`1234` / `4e2d` / `nvzi`）。
- **部件拆字占了 `u` 这个前缀**：以 `u` 开头的英文词会被当成拆字；旧的 `uUnvzi` 写法已失效。
- 常驻的设置窗口是原生 `VMenuSettings.exe`（C# WinForms），占约 17MB 内存；
  这是「秒开」的代价。不想常驻就运行 **`VMenu.exe stop`**（之后 `v`→`1` 会失效，
  改用 `打开设置.bat`）。守护与剪贴板同步子进程（`VMenu.exe watch` / `sync`）各只占约 1MB。
- 设置窗口是 DPI 不感知的，在 150% 缩放下由 Windows 整体放大，布局正常但文字略软。
- 列表的**选中行**用的是系统高亮色（蓝底白字），不是自绘的淡蓝行：改成原生绘制后
  滚动、缩放窗口不再掉帧（自绘那一版每画一格都要回一次 PowerShell，实测慢 4 倍）。
- 设置窗口里的按钮只能**鼠标点**（列表支持双击编辑）。输入法候选栏里的操作行
  （比如「显示更多」）**点不动**：小狼毫的鼠标点击只是「提交这一条候选文字」，
  不会经过按键处理链。所以那条操作行请用键盘 `m` 或 `+`。
- 剪贴板多行内容会被压平成一行（缓存格式是一行一条）。
- 托盘右键菜单里那一项是「**改名 + 改行为**」（菜单仍然是 12 项，不是新增第 13 项）；
  小狼毫**升级 / 修复安装**会把它退回原样，重跑一次安装脚本即可恢复
  （命令见上面「托盘图标右键菜单的变化」）。
