# Rime VMenu 全家桶 1.1.0

**本版主题：语音识别支持 GPU 加速，识别更快、CPU 占用再降一半。**

## 下载哪个？先看你有没有 N 卡

| 文件 | 适合谁 | 大小 |
| --- | --- | --- |
| **`RimeVMenu-Setup-1.1.0.exe`** | **没有 NVIDIA 显卡**（或不想折腾）。语音走 CPU，整机占用约 26% | 约 1.1 GB |
| `RimeVMenu-1.1.0.zip` | 同上，但想手动 / 绿色安装，或用小狼毫官方 `rime-install` 导入配置 | 约 1.1 GB |
| **`RimeVMenu-Setup-1.1.0-GPU.exe`** | **有 NVIDIA 显卡**。自动用 GPU 推理 + 装好 CUDA 运行时，开箱即用 | 约 1.75 GB |
| `RimeVMenu-1.1.0-GPU.zip` | 同上，zip 版 | 约 1.75 GB |

**两个版本功能 100% 一样**，区别只有识别速度和 CPU 占用。
GPU 版多出来的 600 多 MB 是 CUDA 运行时（cuBLAS 等），没 N 卡的话装了也用不上，所以分开出包。

> 不确定？**装 CPU 版就行**——装完打开设置窗口，「语音识别设备」卡片会告诉你检测到了什么。
> 如果它提示「检测到 N 卡但当前是 CPU 版包」，再换 GPU 版即可，换装不会丢词库。
>
> 反过来也不会出错：**GPU 版装在没 N 卡的机器上会自动回落 CPU**，不会报错、不会哑掉。

## GPU 到底快多少

同一台机器（i7-13620H + RTX 5060 Laptop，识别同一段 6.2 秒中文语音）：

| | 1.0.0（默认 16 线程） | CPU 版（4 线程） | **GPU 版（CUDA）** |
| --- | --- | --- | --- |
| 识别耗时 | 0.52 s | 0.43 s | **0.19 s** |
| **整机 CPU 占用** | 59% | 26% | **10.9%** |
| 识别结果 | `今天天气真好，我们去公园散步吧。` | 完全一致 | **完全一致** |

GPU 相比 CPU 版**快约 2.3 倍，CPU 占用再降一半多**。识别率依旧零损失——同一份模型权重，只是算力换了个地方跑。

## 怎么用（不用配置）

设置窗口 →「语音输入」页 → 新增两张卡片：

**① 语音识别设备（GPU 加速）**

- 下拉三选一：**自动（推荐）** / 仅 CPU / 强制 GPU
- 自动 = 能用 GPU 就用，用不了**静默回落 CPU**，不用管
- 卡片上直接显示检测到的显卡型号和显存，以及**当前实际生效的是哪个**
- 没生效时会说清楚**为什么**（没检测到 N 卡 / 装的 CPU 版包 / 手动选了 CPU）

**② 语音识别 CPU 占用**

- 线程数滑块（1 ～ 物理核数），实时显示预估占用档位
- **用 GPU 时滑块自动置灰**并注明「当前用 GPU，线程数不生效」——因为 GPU 推理时 CPU 只做前后处理

不想开设置窗口，直接改 `<小狼毫用户目录>\voice-settings.txt`：

```ini
asr_threads=4
asr_device=auto
```

`asr_device` 填 `auto` / `cpu` / `gpu`，非法值自动退回 `auto`；`asr_threads` 填 `0`、`999`、`abc` 也会退回默认 4。
**改完重新打开一次语音输入（重启悬浮球）生效。**

## 本版修的三个问题

### 1. 设置窗口会悄悄抹掉 CPU 优化配置（1.0.1 遗留 bug）

1.0.1 加了「CPU 占用」设置项，但**设置窗口保存时是整文件重写** `voice-settings.txt`，
只写了标点开关和快捷键两项——于是你只要在设置窗口动一下**任何**语音开关，
`asr_threads=4` 就被静默删掉，llama.cpp 退回默认线程数，**CPU 又被打满**，而且没有任何提示。

现在两个字段都纳入读写，并且做了回归测试（读 → 改 → 写，断言字段仍在）。
顺带修好了 1.0.1 里那张卡片**其实没出现在设置窗口**的问题：当时误加在了遗留的 PowerShell 版本上。

### 2. 包里的 `voice-*.py` 是旧版（有 exe 在跑所以平时看不出）

安装包同时带了两套语音程序：`.exe`（打包好的，启动器优先用）和 `.py`（源码，Python 环境下的回落分支用）。
`.exe` 这次是重新编的、带 GPU 支持，但仓库根目录那两个 `.py` 副本漏了同步 ——
结果是**同一份包里 exe 支持 GPU、py 只有 CPU**。启动器优先走 exe，所以日常使用看不出来；
只有走 `语音输入.bat` / `语音输入-悬浮球.bat` 的 Python 回落分支时才会静默退回 CPU。

现已同步，并在构建脚本里加了**断言**：打包前检查 `voice-overlay.py` / `voice-input.py`
必须认得 `asr_device`，否则直接报错中止，不允许再装出这种混合包。

### 3. CPU 版包里混进 CUDA 运行时

构建时第 1 步会把实时 Rime 目录整个拷进发布树，开发机里如果残留着测试用的 CUDA dll，
就会被一起打进去，让 CPU 版平白胖 600 多 MB。现在打包前会清空目标目录，
并且**两个方向都加了断言**：GPU 版必须带齐 CUDA dll（缺一个后端直接起不来，不是优雅降级），
CPU 版则必须一个都没有。

## 装好的功能

- **`v` 功能菜单** —— 输入法里按 `v`：设置窗口 / 剪贴板 / 快捷输入（计算、日期、农历、序号…）/ 常用语 / 原符号
- **可视化设置窗口**（原生 `VMenuSettings.exe`）—— 词库管理、剪贴板、模糊音开关、语音快捷键、防误触、**语音识别设备 / CPU 占用**
- **剪贴板历史** —— 后台自动记录，`v` → `2` 调用
- **常用语 / 个人词库** —— 设置窗口直接增删改，或用 `加词.bat` / `词库管理.bat`
- **下一个候选词预测** —— 字级二元统计，打完一个字就提示下一个
- **前后鼻音模糊输入** —— an/ang、en/eng、in/ing、ian/iang、uan/uang 五对可单独开关
- **本地语音输入** —— 按住 `Ctrl+Win` 说话、松开上屏，流式输出，全程离线
- **候选框增强** —— 一行 9 个候选，按 `↓` 展开 4×9 方格，长英文自动截断
- **托盘入口** —— 右键托盘图标 →「输入法设置 (S)」

## 环境要求

- Windows 10 / 11 x64
- 小狼毫 [Weasel](https://github.com/rime/weasel)（exe 包在检测不到时会自动拉起内置的 0.17.4 安装器）
- 全程**不需要管理员权限**（装进用户目录、只写 `HKCU`）
- GPU 版另需：NVIDIA 显卡 + 已装驱动（安装包自带 CUDA 运行时，不用单独装 CUDA Toolkit）

## 升级方式

**从 1.0.x 升上来直接覆盖安装即可**，词库、常用语、剪贴板历史都会保留。
CPU 版 ↔ GPU 版之间互相切换也是直接覆盖装，配置和词库都不动。
安装前会自动停掉正在占用模型的 `llama-server.exe`，不会出现「文件被占用装不上」。

## zip 用户：只想更新配置（方式 C）

小狼毫自带 `rime-install.bat` 可直接吃本 zip，但遵守官方规则：**只复制顶层 `*.yaml`、`*.txt` 和 `opencc\`**，
不复制 `lua\`、`cn_dicts\` 和外挂 exe —— 适合给已部署好的机器覆盖更新配置。

```bat
"C:\Program Files\Rime\weasel-0.17.4\rime-install.bat" C:\RimePkg\RimeVMenu-1.1.0.zip
```

> ⚠️ zip 路径**不能有空格、也不能加引号**（`rime-install.bat` 自身解析不了，会报 batch 语法错或误当成包名去 GitHub 下载）。请先把 zip 挪到无空格目录。

## 卸载

控制面板 →「RimeVMenu 全家桶」卸载：会停后台服务、还原托盘菜单改动、删除安装的文件。
**你自己的词库、常用语、剪贴板历史会保留**（已实测）。

## 从源码构建

```powershell
# CPU 版
powershell -File packaging\build-release.ps1
# GPU 版（需要一份带 CUDA 的 llama.cpp 构建）
powershell -File packaging\build-release.ps1 -Gpu
```

GPU 版要求 `llama.cpp` 目录里有 CUDA 后端（`ggml-cuda.dll` + `cublas64_13.dll` +
`cublasLt64_13.dll` + `cudart64_13.dll`），且**版本必须与 `llama-server.exe` 完全一致**
（CUDA 构建和主程序是同一个 commit 编出来的，混版本会让后端加载失败）。
没有的话用 `-CudaSrc <目录>` 单独指定。

两个包的文件名不同（`-GPU` 后缀），可以共存、互不覆盖。
